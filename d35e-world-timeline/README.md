## 使用

1. 在世界的“管理模组”中启用 **3R 世界时间轴**，重新载入世界。
2. 打开右侧边栏，顶部的 **世界时间** 区块对 GM 和玩家都可见，显示当前日期、时间与场景天气。GM 在这里可快捷推进 1 分钟、10 分钟或 1 小时；玩家只有查看权。
3. 点击 **日历** 打开月历与天气窗口。月历直接读取 Foundry 当前世界历法，因此已由其他日历模组配置的月份、星期、闰日会沿用。所有人可浏览月份和当天记录；GM 可选中日期、填写时分、设为世界时间，并添加或删除当天记录。
   - GM 可在日历中的“导入／导出日历”区块下载 JSON 备份，内容包括当前历法定义和日期记录。导入时先选 JSON，再点“读取并预览”，决定是否导入历法、是否导入记录，以及合并或替换现有记录。默认只导入记录并合并，重复记录会跳过。
   - 支持本模组导出的 JSON，以及 Simple Calendar 的 `{calendar, notes}` JSON（例如它的 Harptos／深水城节日预设）。Simple Calendar 的每年重复节日会保留“每年重复”；普通单日记录会导入。文件月份不同于当前历法时，必须同时导入历法定义。
   - 导入历法会改变世界时间对应的日期显示，但不会推进世界时间，也不会改动正在计时的效果结束秒数。Simple Calendar 的每周／每月重复、跨日记录、月相、权限和提醒不在本模组的日期记录模型内，会跳过或不迁移；导入预览会显示跳过的记录数。天气是各场景设置，不包含在日历 JSON 中。
4. 日历下方显示当前场景天气。GM 可手动设置天气和摄氏气温，或选定气候后启用按日自动生成；自动天气随世界日期变化并按场景分别计算。降雨、雷暴、降雪、暴风雪和大雾会同步到 Foundry 原生场景天气特效。未手动设定或启用自动天气的场景，只显示现有的场景天气，不会被这个 Mod 改写。
5. 点击该区块的 **时间轴**，打开可拖动的详细时间窗口。GM 拖动滑块可预览未来 1 小时、8 小时、24 小时或 7 天内的到期位置；点击 **应用时间** 才会真正推进世界时间。也可用“精确推进”输入数字和单位。玩家可以查看窗口中的效果，但没有推进或改动按钮。
6. 打开右侧 **战斗** 标签，可使用重新设计的战斗界面：当前行动者、先攻顺序、生命值（只对有权限的人显示）、效果图标、3R 动作状态以及回合控制。原有 3R 战斗轮和动作处理仍由系统执行。
7. 在场景中选中 Token，画面右上角会竖排显示该角色的增益、Active Effect 和系统状态。鼠标停在图标上会展开效果说明卡；点击图标可固定说明卡，再点一次关闭。没有选中 Token 时，玩家会看到自己所关联角色的效果；GM 需要选中 Token。
8. 说明卡优先读取效果来源法术的 3R 系统资料，包括射程、目标、持续时间和正文；其他效果读取来源物品或效果本身的说明。找不到来源或说明时会明确提示，不会编造说明。GM 可以从卡片打开时间轴调整时长，右键效果图标经确认后可移除增益或 Active Effect。
9. 对 3R 增益：角色卡中激活已启用“自动化/时间轴”、总时长至少 10 轮的增益，模组自动从激活时记录世界时间终点。先前已经激活的增益，可在时间轴中设置或重置时长。
10. 对 Active Effect：已有 `duration.seconds` 和 `duration.startTime` 的效果会显示倒计时。其他效果可在列表中设置时长。
11. 法术若没有生成增益或 Active Effect，可选中目标 Token，在时间轴顶部新建一个只有名称和计时功能的 Active Effect 标记。

**新施放的法术会自动匹配系统时长。** 模组读取 `spellDurationData` 中的轮、分钟、小时、天及每等级时长，并使用这次施法聊天卡片中的施法者等级。旧版或汉化资料若只保留简单的 `spellDuration` 文本（例如“1 分钟/等级”），也能识别。计时记录放在施法者身上，名称会列出聊天卡片提供的目标；这只负责计时，不会自动赋予法术的攻击、伤害等数值效果。

GM 可用详细时间轴的按钮推进 1 分钟、10 分钟、1 小时或 8 小时。其他日历模组推进的世界时间也会触发到期检查。到期时，3R 增益被停用，Active Effect 被删除；D35E 原有停用和删除钩子负责同步其效果。非 GM 可以查看自己有查看权限的角色效果，但不能改动计时。

## 边界

- 3R 的原生时间轴以轮为单位，按每轮 6 秒换算。模组保存绝对结束时间，战斗中的原生轮计时仍可先行结束同一个增益；两套时间不会相加扣除。
- 已经激活的增益没有可靠的历史激活时点，安装模组后不会猜测起点。
- 模组只读取系统的时长字段，不从法术正文推断时长；系统字段缺失、写法复杂或公式无法计算时仍需手动设置。
- 无法确定具体长度的“专注”“直到解除”“见描述”、永久和瞬发法术不会自动计时。以前发出的聊天卡片没有可靠的施法世界时间，不会补算；重新施法后会自动追踪。
- 若启用了 Times Up，它负责处理原生 Active Effect 时长；本模组仍处理自己设置的计时标记。
- 倒退世界时间不会复活已到期的增益或 Active Effect。当前版本只扫描世界角色和当前场景中未链接的 Token 角色。
- 战斗界面替换 D35E 战斗追踪器的外观与布局；它沿用系统及 Foundry 的战斗操作，不改变先攻、回合和增益结算规则。其他会替换战斗追踪器界面的模组可能发生外观冲突。
- D35E 系统没有原生天气生成器；PF2e 系统目录中也没有独立可移植的天气模块。这里提供相近的天气选择、气温、按日生成和场景特效。不会直接复制 PF2e 或 Simple Timekeeping 的天气代码、数据和图标。
- 若另一个模组也会自动修改同一场景的天气特效，应只让一个工具负责写入；本 Mod 的“停止接管”会停止后续自动更新，但保留场景当前特效。
- 导入的历法由本模组保存在世界设置，并通过 Foundry 14 的世界历法接口加载。若另一个模组也负责设置世界历法，应只让一个模组负责历法定义；多个模组同时写入时，最终显示可能受加载顺序影响。
- 本次未在实际 Foundry 世界中运行或测试，首次使用请重载世界后由你按自己的流程检查显示与操作。
