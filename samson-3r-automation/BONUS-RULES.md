# 加值类型与叠加

2026-10-01。依据用户提供的叠加规则，以及本机 D35E 3.1.0 源码。下面是计算规则与写入说明；没有执行测试，也没有观察 Foundry 内的实际结果。

## 计算规则

- 同一项检定／数值上，不同类型加值相加。同类型正数只取最高，闪避和符合条件的环境加值例外。
- 闪避：不同效果可以相加。同一效果的重复实例不重复计算。失去 AC 的敏捷加值时，闪避加值失效。
- 环境：不同境况可以相加。同一境况只取最高。两套精制小偷工具都属于同一境况，不会给开锁 +4。
- 无名加值：不同效果可以相加。同一效果不因重复导入或重复施加而多算。
- 同类型负数只取最严重的一份。原规则没有注明类型的减值按效果来源处理，不能把所有状态减值一律归为同一种、只扣一次。
- 每项属性的内在加值最多 +5。
- 全部攻击与近战／远程、全部伤害与武器／法术、全部豁免与某项豁免、全部技能与单项技能，会在实际受影响的项目上比较。例如“全部豁免 +2 抗力”和“反射 +3 抗力”，反射总共获得 +3 抗力。
- 普通 AC 与接触／措手不及 AC 分开比较。盔甲、盾牌、天生防御不加入接触 AC。它们与作用于自身的增强分别记录，不能把“盔甲增强”误当成“属性增强”。

## 类型对照

| 类型 | 大白话及本次用途 | D35E 字段 |
| --- | --- | --- |
| 炼金 Alchemical | 化学制品带来的收益 | `alchemical` |
| 盔甲 Armor | 盔甲或力场提供的防御 | `armor`；原生盔甲使用 `aac/base` |
| 环境 Circumstance | 工具、位置等境况；不同境况才相加 | `circumstance` |
| 表现 Competence | 做某件事更熟练；增强交涉、一对一交谈 | `competence` |
| 偏斜 Deflection | 偏转攻击；虔诚护盾、守护、誓约防护 | `deflection` |
| 闪避 Dodge | 躲开攻击；失去敏捷防御时失效 | `dodge` |
| 增强 Enhancement | 增强某件武器、防具或某项属性 | `enh` |
| 内在 Inherent | 属性的内在提高；每项最多 +5 | `inherent` |
| 洞察 Insight | 看穿事物；知识虔诚 | `insight` |
| 幸运 Luck | 好运；神恩、天佑者提高原有幸运数值 | `luck` |
| 士气 Morale | 信心；守律履约检定 | `morale` |
| 天生防御 Natural Armor | 皮肤、鳞片等防护 | `naturalArmor`；原生使用 `nac/base` |
| 亵渎 Profane | 邪恶力量 | `profane` |
| 种族 Racial | 种族能力；属性调整、生命之缚 | `racial` |
| 抗力（反抗）Resistance | 抵抗魔法等；守护与誓约的豁免 | `resist` |
| 神圣 Sacred | 善良力量 | `sacred` |
| 盾牌 Shield | 盾牌或盾牌力场 | `shield`；原生使用 `sac/base` |
| 体型 Size Modifier | 尺寸带来的修正 | `size` |
| 背景 Trait | PF 背景特性；反制者的先攻 +2 | `trait` |
| 无名加值 Untyped | 原规则没有指定类型；专攻、陷阱寻找等 | `untyped` |

`base` 是系统的计算字段，不能因此把原文的盔甲加值改说成可叠加的另一种加值。`replace`、`base-replace` 表示替换已有数值，不是额外加值。

## 写入和证据边界

- 原规则未明确写出类型的加值一律称“无名加值”，内部字段为 untyped；不能按来源猜类型。法术正文不附加本维护文件的教程或天佑者等其他能力的联动说明。
- `bonus-types.js` 只提供类型映射并清理旧生成段，`item-data.js` 在种子迁移后修复文字。`presentation.js` 从原生 sourceDetails 读取实际采用的来源、类型和数值；值不能匹配时明确提示来源未记录，不编造明细。
- 用户后续纠正：明细行只显示类型，例如“幸运加值”；同类型同正负号的实际采用数值合并展示，来源仅内部保存，正负分行。显示整理不改变原生叠加或掷骰总值。
- `stacking.js` 在本模组加载后，用临时数据适配 D35E 的公开计算入口；没有改写系统源码，也不把内部比较分组写回物品。物品本身和装备中的增强条目都会参与比较。
- 未注明类型的本模组效果按效果标识防止重复。环境可以用 `circumstanceGroup` 明确指定同一境况；无法只凭两个不同名称判断它们在规则上是否属于同一境况。
- 任意手写在攻击公式、宏、第三方 `combatChanges` 或 Active Effect 公式里的“+2”，若没有类型信息，不能被自动辨认为幸运／增强。本适配没有宣称接管所有第三方计算路径。
- 阅读依据：本机 `actorUpdater.js` 的 `updateChanges`、`#parseChange`、`getReducedMovementSpeed`；`actorChangesHelper.js` 的 `getChangeFlat`；`rolls.js` 的 `rollAttack`／`rollDamage`；`chatAttack.js` 的原生攻击／伤害调用。
- 只核对了文件与这些调用关系。没有执行测试、语法检查、浏览器操作或 Foundry 运行验证；没有写入“用户已验收”。
